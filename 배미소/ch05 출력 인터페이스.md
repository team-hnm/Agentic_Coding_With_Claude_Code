# 출력 스타일 커스터마이징

## 출력 스타일의 핵심 개념

- 출력 스타일이란 클로드 코드가 응답을 생성할 때 따르는 가이드라인의 집합이다.
- 클로드 코드의 시스템 프롬프트를 직접 수정하여 응답의 근본적인 특성을 바꾼다.

## 내장 출력 스타일

- Default: 개발 작업에 최적화된 기본 시스템 프롬프트
- Proactive: 클로드가 더 적극적으로 실행하도록 유도하는 스타일. 확인 없이 합리적으로 가정하고 바로 실행한다.
- Explanatory: 작업하면서 구현 선택에 대한 인사이트를 함께 제공
- Learning: 실습형 스타일. 인사이트 제공하며, 코드에 **`TODO(human)`**  표시를 남겨 사용자가 직접 코드를 작성하도록 유도한다.

### 변경 방법

- `/config` → Output style 메뉴에서 선택
- 설정 파일에 outputStyle 직접 작성

## 커스텀 출력 스타일 생성

- 디렉토리 구조
    - 사용자 레벨 스타일: `~/.claude/output-styles/my-style.md`
    - 프로젝트 레벨 스타일: `.claude/output-styles/team-style.md`
- 프론트매터 필드

    | 필드 | 역할 | 기본값 |
    | --- | --- | --- |
    | `name` | 스타일 이름 | 파일명 |
    | `description` | 선택 목록에 표시될 설명 | 없음 |
    | `keep-coding-instructions` | 코딩 지침 유지 여부 | `false` |
    | `force-for-plugin` | (플러그인 전용). 활성화 시 자동 적용, 사용자의 `outputStyle` 설정을 덮어씀 | `false` |

## 관련 기능과 비교

- Output Style: 시스템 프롬프트 수정
- CLAUDE.md: 시스템 프롬프트에 추가 지침 덧붙임
- 출력 스타일은 메인 대화에만 적용되며, 서브에이전트는 독립적인 시스템 프롬프트로 돌기 떄문에 영향을 받지 않음

## 출력 스타일에서 환각 방지 지침

- URL 및 출처 검증: WebFetch/WebSearch가 실제로 반환한 URL만 인용, 패턴으로 추측한 URL 절대 금지
- 불확실성 표현 허용: 모르면 모른다고 답하도록 명시
- 도구 결과 기반 응답 강제
- 팀 프로젝트라면 `.claude/output-styles/`에 표준 스타일을 커밋해서 팀 전체에 같은 기준을 적용할 수 있다.

# 상태 표시줄

## 상태 표시줄 설정 방법

- `/statusline` 명령에 원하는 내용을 자연어로 입력하면 스크립트를 만들고 설정까지 자동으로 잡아준다.
- 설정 파일 직접 편집
    - `~/.claude/settings.json` 에 `statusLine` 을 정의한다.
        ```json
        {
          "statusLine": {
            "type": "command",                    // 실행 방식 판별자, 현재는 "command"만 지원
            "command": "~/.claude/statusline.sh", // 실행할 스크립트 경로
            "padding": 2                          // 좌우 여백(문자 수), 기본 0
          }
        }
        ```

## 상태 표시줄 스크립트 작동 원리

- 클로드 코드가 JSON을 stdin으로 넘기고 → 스크립트가 가공해서 stdout으로 출력하면 → 그게 그대로 표시된다.
- 출력은 여러 줄 가능, ANSI 색상 코드 지원
- [🔗 JSON 데이터 구조](https://code.claude.com/docs/ko/statusline#available-data)
