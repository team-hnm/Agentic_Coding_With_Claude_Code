# 학습 목표

1. 오케스트레이터-워커 패턴을 기반으로 한 에이전트 위임 학습
2. 에이전트 컨텍스트 격리 학습
3. 에이전트 팀의 작동 원리 학습

# 내용 정리

## 서브에이전트의 개념과 아키텍처

### 서브에이전트란?

- 클로드 코드의 Agent 도구로 호출되는 특화된 AI 어시스턴트
- 각자 독립된 컨텍스트 윈도우, 커스텀 시스템 프롬프트, 도구를 가지고 있고, 작업이 끝나면 핵심 결과만 메인 대화로 반환한다.
- 스킬처럼 마크다운 파일(YAML 프론트매터 + 본문)로 정의한다.
    - 프론트매터: 에이전트 메타데이터
    - 본문: 시스템 프롬프트 (역할, 동작 방식, 제약 조건 등)

### 에이전트 위임 패턴: 오케스트레이터 - 워커

- 서브에이전트 시스템은 **오케스트레이터-워커 패턴**을 따른다.
- 메인 에이전트가 오케스트레이터(작업 분배 + 결과 통합) 역할을 하며, 서브에이전트는 워커 역할을 한다.

### 단일 책임 원칙과 서브에이전트

- 에이전트가 여러 역할을 담당하면 프롬프트가 복잡해지고 결과 예측이 어려워진다.
- **하나의 서브에이전트는 하나의 책임만 맡도록 설계**한다. (코드 리뷰 담당 vs 테스트 작성 담당을 분리하는 식)

### 컨텍스트 엔지니어링 원칙

- **컨텍스트 엔지니어링**: 모델에 제공하는 컨텍스트를 체계적으로 설계하는 방법론
- 지침은 **적정 고도**로 작성한다. (방향은 주되 판단할 여지는 남겨야 한다)

  > **💡 책에는 "에이전트에 방향을 줄 만큼 구체적이되 판단력을 발휘할 여지를 남기는 지침"이라고 작성되어 있는데, 표현이 추상적이어서 관련 내용을 찾아보았다.**
  >
  > 1. 목적(왜 이 작업을 하는지)
  > 2. 문제에 대한 배경(어떤 프로젝트, 어떤 제약 상황인지)
  > 3. 필수 규칙
       > 위 내용을 에이전트에게 설명하고, 구체적인 실행 절차는 에이전트가 스스로 판단하도록 남겨둔다.
- 컨텍스트 엔지니어링을 두 가지 지점에서 각각 관리한다.
    1. **초기 컨텍스트 설계**: 에이전트에 작업 관련 의존성만 전달
    2. **작업 중 수집 컨텍스트 관리**: 불필요하게 컨텍스트가 커지지 않도록 필요한 정보만 수집하게 지침 제공

### 에이전트 체인과 병렬 실행

- **순차 실행**: 이전 에이전트의 결과가 다음 에이전트의 입력이 되는 파이프라인 구조
- **병렬 실행**: 독립적인 작업을 동시에 처리할 때 유용. 각 에이전트가 서로의 컨텍스트를 오염시키지 않도록 격리된다.
- 체인 설계 시 각 단계의 입출력 형식을 명확히 정의해야 한다. (이전 출력이 다음 기대 입력과 다르면 파이프라인이 깨질 수 있음)
- **다중 클로드 워크플로 (multi-claude workflow)**: 여러 클로드 코드 인스턴스를 서로 다른 터미널에서 병렬로 실행해 복잡한 작업을 처리하는 패턴

## 서브에이전트 사용하기

클로드 코드는 🔗 내장 서브에이전트 커스텀 서브에이전트를 지원하며, Agent 도구를 통해 이들을 호출한다.

### 에이전트 결과 통합

- 서브에이전트가 작업을 완료하면 결과가 메인 대화로 반환된다.
- 단일 에이전트의 결과는 후속 작업으로 바로 활용할 수도 있고, 여러 에이전트의 결과를 모아 종합적인 결론을 만들 수도 있다.
- 결과를 통합할 때는 정보의 우선순위를 고려해야 한다. 여러 에이전트가 상충하는 의견을 제시할 수 있기 때문이다. (메인 에이전트의 역할)

### 작업 재개 기능 활용

- 서브에이전트는 기본적으로 호출할 때마다 새 인스턴스로 시작하므로 이전 작업을 이어가려면 작업 재개를 명시적으로 사용해야 한다.
- 장시간 진행되는 연구나 분석 작업에서 특히 유용하다.
- 각 서브에이전트 실행에는 고유한 `agentId`가 할당되며, 이 ID를 사용해 에이전트를 재개할 수 있다.
- 재개 시 이전 대화의 전체 컨텍스트가 로드된다.
- 대화 내용은 `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl` 파일에 저장된다. 재개 요청 시 이 파일을 읽어 이전 컨텍스트를 복원한 뒤 새로운 지시사항을 추가하여 계속 실행한다.
- 작업을 재개할 때는 프롬프트에 자연어로 해당 `agentId` 를 재개해달라고 요청한다.

### 에러 처리 및 복구

- 파일 접근 오류: 경로와 권한 설정을 확인한다.
- 명령 실행 실패: 명령어 구문과 환경 설정을 점검한다.
- 컨텍스트 초과: 작업 범위를 줄이거나 `/clear` 후 다시 시도한다.

### 서브에이전트 성능 측정

- **작업 완료 시간**: 작업 시작부터 결과 반환까지 걸린 시간이다. 같은 유형의 작업끼리 비교하면 효율성을 평가할 수 있다.
- **결과 품질**: 결과의 정확성과 실제 활용 가능성을 평가한다.
- **컨텍스트 사용량**: 작업 중 소비한 토큰 양이다. 완료 후 각 에이전트의 측정 지표를 보고하도록 요청하면 비교에 활용할 수 있다.

## 커스텀 서브에이전트 개발과 스킬 주입

### YAML 프론트매터 완전 가이드

| 필드 | 설명 |
| --- | --- |
| `name` | 고유 식별자 |
| `description` | 에이전트 목적 설명 |
| `tools` | 사용할 수 있는 도구를 명시(생략 시 부모 도구 그대로 상속) |
| `disallowedTools` | 사용할 수 없는 도구를 지정(`tools`와 함께 사용 불가) |
| `permissionMode` | 도구 실행 시 권한 확인 방식 |
| `skills` | 주입할 스킬 목록 |
| `hooks` | 특정 시점에 자동으로 실행할 작업 |
| `memory` | 세션 간 기억을 유지 |
- `permissionMode`: 도구 실행 시 권한 확인 방식을 결정한다.

    | 모드 | 동작 방식 | 사용 용도 |
    | --- | --- | --- |
    | **default** | 표준 권한 확인 | 범용 에이전트 |
    | **acceptEdits** | 파일 편집 작업을 자동 승인 | 신뢰할 수 있는 구현 에이전트 |
    | **dontAsk** | 확인 없이 진행, 미승인 도구는 거부 | 엄격한 샌드박스 에이전트 |
    | **bypassPermissions** | 모든 권한 프롬프트 생략 | 완전 자동화 파이프라인 |
    | **plan** | 읽기 전용, 수정·실행 불가 | 연구/분석 에이전트 |

- `hooks`: 에이전트 실행 중 특정 시점에 자동으로 셸 명령을 실행하는 기능이다.
    - `PreToolUse`: 도구 실행 직전
    - `PostToolUse`: 도구 실행 직후
    - `Stop`: 작업 종료 시

    ```markdown
    name: code-reviewer
    description: React 코드 리뷰 전용 에이전트
    
    hooks:
      PreToolUse:
        - npm run lint
    
      PostToolUse:
        - echo "Review completed"
    
      Stop:
        - echo "Agent finished"
    ```

- `memory`: 에이전트가 프로젝트 지식을 장기간 유지하는 기능이다. 설정 시 `MEMORY.md`가 자동으로 컨텍스트에 포함되고 메모리 읽기/쓰기 기능이 활성화된다.
- `skills`: 특정 도메인의 전문 지식을 에이전트에 제공한다.
    - 여러 개를 지정할 수 있으며 앞에서부터 우선적으로 적용된다.
    - **일반 규칙 → 특수 규칙 → 프로젝트 규칙** 순의 배치가 권장된다.
- 서로 다른 방법론을 지시하는 스킬을 함께 지정하면 에이전트의 동작이 일관되지 않을 수 있다.
- 기본 조합은 **기반 스킬 + 도메인 스킬**이다. 기반 스킬은 공통 규칙과 원칙을, 도메인 스킬은 특정 분야 지식을 제공하며, 상위 스킬이 하위 스킬을 참조하도록 구성하면 계층적 지식 구조를 만들 수 있다.
- **역할 특화 조합**은 에이전트의 특정 역할에 필요한 스킬만 선별해서 조합하는 방식이다.
    - 예시)
        - **코드리뷰 에이전트**: 코딩 표준 + 코드 품질 메트릭 + 리뷰 체크리스트 스킬
        - **성능 최적화 에이전트**: 웹바이탈 측정 스킬 + 번들 크기 분석 스킬 + Next.js 렌더링 최적화 스킬만 조합
        - **배포 전 점검 에이전트**: 변경사항 요약(changelog) 스킬 + 배포 체크리스트 스킬 + 환경변수 검증 스킬만 조합

### 프롬프트 작성 가이드

좋은 프롬프트는 에이전트가 무엇을, 어떻게, 어떤 형식으로 결과를 내야 하는지를 구체적이고 명확하게 명시한다.

- **출력 포맷 지정**
    - 포맷을 지정하면 결과의 일관성과 활용도가 높아진다.
    - JSON, 마크다운, 텍스트 등 다양한 형식을 지정할 수 있다.
- **경계 조건 명시**
    - 에이전트가 처리하지 않아야 할 상황을 명확히 정의한다.
    - 수행하는 작업과 수행하지 않는 작업을 모두 명확히 작성한다.
    - 범위 밖 요청이 들어왔을 때 어떻게 대응할지도 함께 지정해두면 좋다.

### 에이전트 테스트와 최적화

**테스트**
- **정상 케이스**: 에이전트가 설계된 목적대로 잘 동작하는지 확인한다.
- **경계 케이스**: 입력이 비어있거나 매우 크거나, 예상치 못한 형식일 때를 테스트한다.
- **실패 케이스**: 에이전트가 처리 불가능한 상황에서 적절히 대응하는지 확인한다.

**최적화**
- 프롬프트를 다듬거나, 도구 권한을 조정하거나, 스킬 조합을 바꾸는 방식으로 진행한다.
- 응답 시간, 결과 품질, 컨텍스트 사용량을 측정해서 개선점을 찾는다.
- 모델 선택 기준: 비용과 속도가 중요한 작업은 Haiku, 품질이 중요한 일회성 분석 작업은 Opus를 쓴다.

## 에이전트 팀

### 에이전트 팀의 핵심 개념

- 클로드 코드 인스턴스 여러 개를 하나의 팀처럼 묶어서 함께 작업하도록 하는 기능이다.
- 하나의 세션(메인 에이전트)이 팀 리더 역할을 맡아 작업을 조율하고 업무를 분배하며 결과를 종합한다.
- 팀원(클로드 코드 인스턴스)은 각각 독립된 컨텍스트 윈도우에서 작업하며, 팀원끼리 서로 소통할 수 있다.
- 서브에이전트는 일 끝나면 바로 사라지지만, 팀원은 팀이 해산되기 전까지 자기 컨텍스트를 그대로 들고 여러 태스크를 이어서 처리한다.

### 팀 생성과 생애 주기 관리

- `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`  환경변수를 1로 설정하면 활성화할 수 있다.
- 에이전트 팀의 아키텍처
    - 팀 리더
    - 팀원
    - 태스크 목록: 팀원들이 선택하고 작업하는 공유 작업 큐
    - 메일박스: 팀원끼리 통신을 위한 메시징 시스템
- 팀원의 수는 클로드가 태스크에 따라 결정하거나 사용자가 지정할 수 있다.
- 팀원의 종료는 리더가 종료 요청을 보내고, 팀원은 이를 승인하여 정상 종료하거나 사유를 붙여 거부할 수 있다.
- 팀 정리는 리더에게 요청하면 공유 리소스가 제거된다.

### 메시지 전달 시스템

- `message`: 특정 팀원 한 명에게 메시지를 보내는 방식
- `broadcast`: 모든 팀원에게 동시에 메시지를 보내는 방식
    - 비용이 팀 규모에 비례하여 증가하므로 신중하게 사용해야 한다.
- 사용자가 직접 특정 팀원과 대화하는 것도 가능하다.

### 태스크 조정 시스템

- 태스크는 pending(대기), in progress(진행중), completed(완료) 세 가지 상태를 가진다.
    - 태스크는 다른 태스크에 의존할 수 있다.
    - 의존하는 태스크가 아직 완료되지 않았다면, pending 상태인 후속 태스크는 선택할 수 없다.
- 태스크 할당 방법
    1. 리더가 명시적으로 할당하는 방식
    2. 팀원이 자신의 태스크를 완료한 뒤, 미할당 태스크 중 스스로 선택해 가져가는 자기 선택 방식
- 여러 팀원이 동시에 같은 태스크를 선택하려는 상황을 대비해 파일 잠금이 적용된다. 한 팀원이 태스크를 선택하는 순간 잠금이 걸려, 다른 팀원은 해당 태스크를 가져갈 수 없다.

### 서브에이전트와 에이전트 팀

- 서브에이전트는 결과만 받으면 되는 집중 작업에, 에이전트 팀은 팀원끼리 소통, 검증이 필요한 협업 작업에 적합하다.
- 에이전트 팀은 서로 다른 관점의 조사나 리뷰, 프론트/백엔드/테스트 등 레이어 간 분담 작업처럼 팀원 간 소통과 협업이 필요한 경우에 효과적이다.
- 반대로 순차 작업, 의존성 많은 작업은 서브에이전트나 단일 세션이 효과적이다.

## CLI 기반 동적 에이전트 활용

일회성 작업을 위해 에이전트를 즉석에서 구성하는 방식이다.

### 기존 에이전트 직접 실행

- `—agent` 플래그로 `.claude/agents/` 또는 `~/.claude/agents/`에 정의된 특정 에이전트를 CLI에서 바로 호출할 수 있다.
- 이 방식은 자동화 시나리오에 적합하다.
- `—agent` 플래그로 실행되는 에이전트는 메인세션으로 동작하며, 자신의 `tools` 필드에 지정된 서브에이전트를 생성할 수 있다.

### 인라인 에이전트

- `-agents` 플래그는 JSON 객체를 받아 에이전트를 즉석에서 정의한다. 별도의 마크다운 파일을 만들지 않고도 세션 하나짜리 일회성 에이전트를 구성할 수 있어, 스크립트 자동화나 실험적 테스트에 적합하다.
- JSON 객체의 각 필드는 마크다운 파일의 frontmatter 필드에 대응한다 (`description`, `prompt`, `tools`, `model` 등).
- `skills` 필드는 인라인 정의에서 사용할 수 없으므로, 필요한 지식은 `prompt` 필드에 직접 포함해야 한다.
