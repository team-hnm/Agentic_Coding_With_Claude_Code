# 비대화형 모드와 스크립트 자동화

비대화형 모드는 명령줄에서 프롬프트를 전달하고 결과를 표준 출력으로 받을 수 있어 셸 스크립트, cron 작업, CI/CD 파이프라인 등에서 클로드 코드의 기능을 활용할 수 있다.

## 주요 플래그

### 입출력 형식

- 프롬프트는 `-p`(`--print`) 플래그와 함께 전달하고, [🔗 CLI 옵션](https://code.claude.com/docs/ko/cli-reference#cli-flags)을 사용한다.
- 입력 형식은 `-input-format`으로 지정하며 `text`, `stream-json`을 지원한다.
- 출력 형식은 `-output-format`으로 지정하며 `text`, `json`, `stream-json`(실시간용 줄 단위 JSON)을 지원한다.

### 다중 턴 대화

비대화형 모드에서 대화 컨텍스트를 유지하는 방법

- `—continue` (`-c`)
    - 가장 최근 대화를 불러온다.
    - 코드 리뷰 → 피드백 → 구현처럼 작업을 이어서 진행할 떄 유용하다.
- `—resume` (`-r`)
    - 세션 ID를 지정하여 특정 세션을 재개한다.
    - 여러 단계로 나뉜 작업을 스크립트로 구현할 수 있다.

```bash
# [1] claud -p 로 비대화형 실행: --output-format json 으로 session_id 확보
SESSION_ID=$(claude -p "checkout 변경분을 리뷰해줘" \
  --output-format json | jq -r '.session_id')

# [2] -c (--continue): 현재 디렉터리의 가장 최근 세션을 이어감
claude -c -p "위 리뷰 결과 중 타입 관련 항목만 골라줘"

# [3] --resume <id>: 세션을 ID로 지정해 재개
claude -p --resume "$SESSION_ID" "그 항목들로 릴리즈 노트를 만들어줘"
```

## 프로그래밍 활용

### CI/CD 파이프라인

- 깃헙 액션, 깃랩 CI, 젠킨스 등의 CI/CD 시스템에서 클로드 코드를 비대화형으로 호출해 코드 리뷰, 보안 점검, 문서 생성 등을 자동화할 수 있다.
- CI/CD통합 시 고려해야 할 요소
    - 인증: API 키는 환경변수/시크릿으로 주입하고, 로그에 노출되지 않게 한다.
    - 타임아웃: `timeout` 명령으로 클로드 코드 실행 시간을 제한한다.
    - 오류 처리: `-output-format json`으로 구조화된 응답을 받아 `is_error` 필드로 실패를 판별하고, 실패 시 적절한 종료 코드로 빠져나온다.
    - 비용 관리: `-max-turns`로 에이전트 턴 수를 제한하고, 응답의 `total_cost_usd`를 모니터링한다.
    - 속도 제한: 여러 파일을 연속 처리할 때는 요청 사이에 지연을 넣어 API 속도 제한을 피한다.

### 에이전트 SDK

에이전트 SDK란? 에이전트 루프, 컨텍스트 관리 등의 클로드 코드 기능을 파이썬과 타입스크립트 코드 안에서 직접 활용할 수 있게 해주는 라이브러리

> 💡**클로드 코드의 기능은 CLI로 쓸 수 있는데, 에이전트 SDK를 쓰는 것과 어떤 차이가 있을까?**
>
>
> 누가 클로드를 호출하고 응답 받느냐의 차이이다. 셸이 호출하고 응답받는 경우에는 CLI, 애플리케이션 내에서 호출하고 응답받아 로직을 이어가야 한다면 에이전트 SDK를 활용한다. (제품에 AI 기능을 넣는 경우가 대표적이다. Claude Code Docs의 어시스턴트에 따르면 해당 기능도 에이전트 SDK로 구현되었다고 한다.)
>

### 구조화 출력: —json-schema

- 에이전트가 워크플로우를 완료한 후, 지정한 JSON Schema와 일치하는 검증된 JSON 출력을 받는 플래그
- 클로드 코드의 기본 응답은 텍스트 → 파싱 필요
- 구조화 출력으로 코드에서 바로 쓸 수 있는 데이터를 받을 수 있다.

# 훅 시스템

훅은 클로드 코드의 생애 주기 중 특정 시점에 자동으로 실행되는 핸들러이다. LLM의 자동 판단에 의존하지 않고, 특정 작업이 반드시 실행되도록 보장한다.

### Hook 핸들러 타입

- `command` : 셸 명령 실행. JSON 입력을 stdin에서 받고 종료 코드와 stdout으로 응답
- `http` : 이벤트 JSON 입력을 POST로 전송. JSON 출력 형식을 사용해 응답 본문으로 결과를 전달
- `mcp_tool` : 이미 연결된 MCP 서버의 도구를 호출
- `prompt` : 클로드 모델에 단일 턴 평가를 위한 프롬프트 전송
- `agent` : (실험적 기능) Read·Grep·Glob 같은 도구를 쓰는 서브에이전트를 생성하여 결정을 반환하기 전에 조건을 확인할 수 있다.

## 훅 이벤트

훅 이벤트는 생애 주기의 특정 시점에서 발생하며 사용자는 원하는 이벤트에 훅을 등록하여 자동화 로직을 구현한다.

**훅 이벤트 발생 주기**

- 세션당 1회:**`SessionStart`**, **`SessionEnd`**
- 턴당 1회:**`UserPromptSubmit`**,**`Stop`**,**`StopFailure`**
- 도구 호출마다:**`PreToolUse`**,**`PostToolUse`**

[🔗 대표 이벤트](https://code.claude.com/docs/ko/hooks#hook-events)

| 이벤트 | 발생 시점 |
| --- | --- |
| `SessionStart` | 세션이 시작되거나 재개될 때 |
| `UserPromptSubmit` | 프롬프트를 제출한 뒤, 클로드가 처리하기 전 |
| `PreToolUse` | 도구 호출이 실행되기 전 |
| `PermissionRequest` | 도구 호출에 권한 결정이 필요할 때 |
| `PostToolUse` | 도구 호출이 성공한 뒤 |
| `PostToolUseFailure` | 도구 호출이 실패한 뒤 |
| `Stop` | 클로드가 응답을 마쳤을 때 |
| `SubagentStop` | 서브에이전트가 끝났을 때 |
| `PreCompact` | 컨텍스트 압축 직전 |
| `SessionEnd` | 세션이 종료될 때 |

### 종료 코드와 결정 제어

훅의 실행 결과는 종료코드 또는 JSON 출력으로 클로드 코드에 전달된다.

**종료 코드**

- 종료코드 0: 성공. 클로드 코드는 stdout에서 JSON 출력을 파싱한다.
- 종료코드 2: 차단 오류. 클로드 코드는 stdout과 JSON을 무시하고, stderr 텍스트를 클로드에 오류 메시지로 전달한다.
  [🔗 이벤트별 종료 코드 2 동작](https://code.claude.com/docs/ko/hooks#exit-code-2-behavior-per-event)
- 다른 종료 코드: 차단되지 않는 오류. stderr가 상세 모드에서 표시되고 실행이 계속 된다.

**JSON 출력**

종료 코드를 사용하면 허용 또는 차단할 수 있지만 JSON 출력은 더 세밀한 제어가 가능하다.

| **필드** | **기본값** | **설명**                                                   |
| --- | --- |----------------------------------------------------------|
| **`continue`** | **`true`** | `false`인 경우 hook이 실행된 후 클로드가 완전히 중지된다. 모든 이벤트 특정 결정 필드보다 우선한다. |
| **`stopReason`** | 없음 | `continue`가 `false`일 때 사용자에게 표시되는 메시지                    |
| **`suppressOutput`** | **`false`** | `true`인 경우 디버그 로그에서 stdout을 숨긴다.                         |
| **`systemMessage`** | 없음 | 사용자에게 표시되는 경고 메시지                                        |
| **`terminalSequence`** | 없음 | 클로드 코드가 사용자를 대신하여 내보낼 터미널 이스케이프 시퀀스                      |

### 훅 구성 파일

Hook은 설정 파일(`~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json`, 관리형 정책 설정)과 플러그인 `hooks/hooks.json`, Skill·Subagent frontmatter에서 정의할 수 있으며, 세 가지 중첩 단계를 따른다.

- 1단계: 응답할 훅 이벤트 선택
- 2단계: 발생 시기를 필터링할 매처 그룹 추가
- 3단계: 하나 이상의 훅 핸들러 정의

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "/path/to/lint-check.sh"
          }
        ]
      }
    ]
  }
}
```

[🔗 훅 핸들러 공통 필드](https://code.claude.com/docs/ko/hooks#common-fields)

### 매처 패턴

- `matcher`  필드는 훅이 발생할 때를 필터링한다.
- 각 이벤트 유형마다 매처가 필터링 하는 대상이 다르다.

  | 이벤트 | 매처가 필터링하는 것 | 예제 matcher 값 |
  | --- | --- | --- |
  | `PreToolUse`, `PostToolUse` 등 | 도구 이름 | `Bash`, `Edit\|Write` |
  | `SessionStart` | 세션이 시작된 방식 | `startup`, `resume`, `clear`, `compact` |
  | `FileChanged` | 감시할 파일명 | `.envrc\|.env` |
  | `SubagentStart` | 에이전트 유형 | `general-purpose`, `Explore` |
  | `ConfigChange` | 구성 소스 | `user_settings`, `skills` |
  | `UserPromptSubmit`, `Stop` 등 | 매처 없음 | 항상 발생 |

### 프롬프트 기반 훅과 에이전트 기반 훅

**프롬프트 기반 훅 (`type: “prompt”`)**

- 훅 입력과 프롬프트를 클로드 모델에 전송하여 단일 턴 평가를 수행한다.
- 모델은 yes/no 결정을 JSON으로 반환하며, 클로드 코드가 이 결정을 자동으로 처리한다.
- `prompt` 필드에 프롬프트 텍스트를 쓰고, `$ARGUMENTS`가 훅 입력 JSON의 자리 표시자다. `model`은 선택이며 기본값은 빠른 모델이다.

    ```json
    {
      "hooks": {
        "Stop": [
          {
            "hooks": [
              {
                "type": "prompt",
                "prompt": "Claude가 작업을 종료해도 되는지 판단해줘: $ARGUMENTS. 요청된 작업이 모두 완료되었는지 확인해줘."
              }
            ]
          }
        ]
      }
    }
    ```


**에이전트 기반 훅 (`type: “agent”`)**

- 단일 LLM 호출 대신 Read, Grep, Glob 같은 도구를 사용할 수 있는 서브에이전트를 생성하여 다중 턴 검증을 수행한다.
- 실험적 기능이며 변경될 수 있다.

### 비동기 훅

- hook 구성에 `"async": true`를 추가하여 클로드의 실행을 차단하지 않고 백그라운드에서 실행할 수 있다.
- 비동기 훅은 `type: "command"` 에서만 지원된다.
- 백그라운드 프로세스가 종료된 후 훅이 `additionalContext` 필드가 있는 JSON 응답을 생성한 경우, 다음 대화 턴에서 클로드에게 전달된다. `systemMessage` 필드는 클로드가 아닌 사용자에게 표시된다.

### 프론트매터 훅과 에이전트 범위 훅

- 훅은 설정 파일 외에 스킬이나 서브에이전트의 YAML 프론트매터에 직접 정의할 수 있다.

    ```yaml
    ---
    name: form-builder
    description: 폼 빌더 생성
    hooks:
      PostToolUse:
        - matcher: "Write|Edit"
          hooks:
            - type: command
              command: "./scripts/check-zod.sh"
    ---
    ```

- 스킬 훅을 한 번만 실행하려면 `once: true`를 설정한다.
- `once`는 스킬 프론트매터에서만 유효하며, 설정 파일과 에이전트 프론트매터에서는 무시된다.
- 프론트매터 훅은 해당 컴포넌트의 컨텍스트에서만 추가로 활성화된다. 서브에이전트는 실행이 끝나면 정리되고, 스킬은 세션이 끝날 때까지 유지된다.

### 훅 실행의 특성

- 동일한 이벤트에 대해 여러 훅이 등록되어 있으면 병렬로 실행된다.
- 완전히 동일한 훅 핸들러는 자동으로 중복으로 제거된다
- 기본 시간 제한은 `command`, `http`, `mcp_tool` 600초, `prompt` 30초, `agent` 60초이며,  `timeout` 필드로 별도 설정이 가능하다.

### HTTP 훅

- `type: "http"`로 지정하며, 이벤트의 JSON 입력을 지정된 URL로 POST 요청해 원격 서비스와 연동한다.
- 요청 본문은 `Content-Type: application/json`으로 전송되며, command 훅이 stdin으로 받는 것과 동일한 JSON이다.
- 응답 본문은 command 훅의 stdout과 동일한 JSON 출력 형식을 사용한다.
- 팀 공유 감사 서비스, 중앙 로깅, 알림 서비스 등 외부 시스템 통합에 적합하다.
- 로컬 셸 명령 실행이 어려운 환경에서도 연동을 구현할 수 있어 command 타입의 보완 역할을 한다.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "http",
            "url": "http://localhost:8080/hooks/pre-tool-use",
            "timeout": 30,
            "headers": {
              "Authorization": "Bearer $MY_TOKEN"
            },
            "allowedEnvVars": ["MY_TOKEN"]
          }
        ]
      }
    ]
  }
}
```

# MCP 통합으로 외부 세계와의 연결 확장

## MCP 전송 방식

MCP 전송 방식은 **Claude Code 같은 MCP 클라이언트와 MCP 서버가 메시지를 주고받는 방법**이다.

### stdio 전송

- 로컬에서 실행되는 MCP 서버와 표준 입출력을 통해 통신하는 방식이다.
- 로컬 파일이나 개발 환경처럼 사용자의 컴퓨터에서 실행되어야 하는 도구에 적합하다.

### HTTP 전송

- 원격 MCP 서버와 HTTP를 통해 통신하는 방식이다.
- 클라우드에서 호스팅되는 MCP 서버와 연결할 때 사용한다.
- 인증 헤더나 OAuth 등의 설정을 지원한다.

### SSE(Server-Sent Events) 전송

- 기존에 SSE를 사용하던 서버가 아직 HTTP 전송으로 마이그레이션하지 않은 경우에만 사용한다.
- 권장되지 않는 방식이다.

> **💡SSE란 무엇이고, 왜 권장되지 않을까?**
>
> SSE는 서버가 클라이언트로 데이터를 지속적으로 전달하기 위한 일반적인 HTTP 기술이다. 과거 MCP는 양방향 통신을 위해 `클라이언트 → 서버는 HTTP POST`, `서버 → 클라이언트는 SSE`로 역할을 나눴지만, 현재는 Streamable HTTP로 이를 하나의 MCP endpoint 중심으로 통합되었다.
>

### 원격 WebSocket 전송

- WebSocket은 클라이언트와 서버가 하나의 연결을 계속 유지하며 양방향으로 데이터를 주고받는 방식이다.
- 외부 이벤트를 클로드에게 푸시하는 원격 MCP 서버에 적합하다.

## MCP 서버 설정과 구현 방법

- 클로드 코드는 로컬, 프로젝트, 사용자 범위의 구성을 지원한다.
- `.mcp.json` 구성과 환경 변수 확장
  - `.mcp.json` 파일은 프로젝트 루트 디렉터리에 위치하며 프로젝트 범위으 MCP 서버를 정의한다.
  - 환경 변수 확장 기능을 통해 민감한 정보를 관리할 수 있다.

      ```json
      {
        "mcpServers": {
          "api-server": {
            "type": "http",
            "url": "${API_BASE_URL:-https://api.example.com}/mcp",
            "headers": {
              "Authorization": "Bearer ${API_KEY}"
            }
          }
        }
      }
      ```

    - `${VAR}` : 환경변수 참조
    - `${VAR:-default}` : `VAR` 이 설정되면 확장, 그렇지 않으면 defualt 사용
- `/mcp` 또는 `claude mcp login <name>` 로 OAuth 인증을 사용할 수 있으며, OAuth를 지원하지 않는 서버는 헤더기반 인증을 사용할 수 있다.

# 플러그인 시스템 이해하기

플러그인은 슬래시 명령, 에이전트, 훅(Hooks), MCP 서버 같은 **클로드 코드의 확장 기능을 하나의 패키지로 묶어 설치·공유할 수 있게 해주는 기능**이다. 팀이나 여러 프로젝트에서 재사용하고 버전 관리하기에 유용하다.

## 플러그인 구조

```json
my-plugin/                          # 플러그인 루트 디렉터리 (마켓플레이스에 등록되는 단위)
├── .claude-plugin/
│   └── plugin.json                 # 플러그인 메타데이터(이름, 설명, 버전 등)만 포함
│                                    # 다른 파일은 이 폴더 안에 두지 않음
│
├── commands/                       # 슬래시 명령 정의 (예: /my-plugin:review)
│   └── review.md
│
├── agents/                         # 전문 서브에이전트 정의
│   └── code-reviewer.md
│
├── hooks/                          # 특정 이벤트(파일 저장, 명령 실행 등)에 반응하는 훅 설정
│   └── hooks.json
│
├── skills/                         # Agent Skills - Claude가 작업 맥락에 따라 자동으로 사용
│   └── code-review/
│       └── SKILL.md                # YAML frontmatter(description 등) + 지침 본문
│                                    # ※ 스킬이 하나뿐이면 skills/ 없이
│                                    #   SKILL.md를 루트에 바로 둬도 됨
│
├── .mcp.json                       # 이 플러그인이 제공하는 MCP 서버 설정
│                                    # (~/.claude/.mcp.json이 아니라 반드시 플러그인 루트에 위치)
│
└── settings.json                   # 플러그인 활성화 시 적용할 기본 설정
                                     # (현재 agent, subagentStatusLine 키만 지원)
```

## 컴포넌트 유형

### 에이전트 컴포넌트

- `agents/` 디렉터리에 에이전트 정의 파일을 배치하면 특정 작업에 특화된 서브에이전트를 추가할 수 있다.
- `name`과 `description`을 필수로 작성하며, `tools`, `model`, `skills`, `maxTurns` 등을 선택적으로 설정할 수 있다.
- 클로드는 `description`을 보고 해당 작업을 서브에이전트에게 위임할지 판단한다.

### 스킬 컴포넌트

- Skill은 특정 작업을 수행하기 위한 재사용 가능한 지침 묶음이다.
- `skills/<skill-name>/SKILL.md` 형태로 정의한다.
- 설치된 플러그인의 Skill은 `/plugin-name:skill-name` 형태로 사용자가 호출하거나, 클로드가 작업 맥락을 보고 적절한 Skill을 자동으로 호출할 수 있다.

### 훅 컴포넌트

- 훅은 클로드코드에서 특정 이벤트가 발생했을 때 자동으로 실행되는 이벤트 핸들러다.
- `hooks/hooks.json` 또는 `plugin.json`에 직접 정의한다.
- 세션 시작, 사용자 프롬프트 제출, 도구 실행 전·후, 파일 변경, 서브에이전트 시작·종료 등에 반응할 수 있다.

### MCP 서버 컴포넌트

- 플러그인은 외부 도구 및 서비스와 연결하기 위한 MCP 서버를 함께 제공할 수 있다.
- 플러그인 루트의 `.mcp.json` 또는 `plugin.json`에 정의한다.
- 플러그인이 활성화되면 해당 MCP 서버도 연결되어 클로드가 제공되는 MCP Tool을 사용할 수 있다.

### LSP 서버 컴포넌트

- 플러그인은 LSP 서버 설정을 제공해, 코드베이스에서 작업할 때 클로드에게 정의 이동, 참조 찾기, 타입 및 문서 제공 등 실시간 코드 인텔리전스를 제공한다.
- `.lsp.json`또는`plugin.json`에 인라인으로 정의한다.

> 💡**LSP(Language Server Protocol)란?**
>
> 코드 편집기·IDE와 언어별 분석 도구(언어 서버) 사이의 통신 방식을 표준화한 프로토콜이다.
>
> 예를 들어 TypeScript에서는 `typescript-language-server`가 코드를 분석하고, 클로드 코드가 LSP를 통해 정의 위치나 타입 정보를 바로 받을 수 있다. 클로드 코드가 단순히 파일 내용을 문자열로 검색하는 것보다 언어의 구조를 이해하면서 코드를 탐색할 수 있게 해준다.
>

> **💡클로드 코드는 기본적으로 파일을 읽고, 쓰고, 편집하는 기능을 할 수 있는데 언제 LSP 서버를 사용하는 게 효율적일까?**
>
> LSP를 사용하면 **언어 서버가 분석한 정의·참조·타입·진단 정보 등을 바로 활용**할 수 있다. 따라서 단순한 수정 작업보다는 **대규모 리팩터링이나 코드 탐색**에서 효과가 크다.
>
> 예를 들어 공통 타입이나 함수의 사용처를 모두 찾아 변경해야 할 때, 문자열 검색보다 실제 symbol 기준으로 참조를 찾을 수 있어 더 정확하다.
>
> 코드 수정 후 발생한 타입 오류도 Language Server의 diagnostic을 통해 빠르게 확인할 수 있다.
>
> 정리하자면, **추론해야 할 코드 정보를 언어 서버에서 정확하게 제공해 탐색과 수정의 신뢰도를 높일 수 있다.**
>

## 플러그인 설치 범위

| **범위** | **설정 파일** | **사용 사례** |
| --- | --- | --- |
| **`user`** | **`~/.claude/settings.json`** | 모든 프로젝트에서 사용할 개인 플러그인. 기본값 |
| **`project`** | **`.claude/settings.json`** | Git으로 공유하여 팀이 함께 사용하는 플러그인 |
| **`local`** | **`.claude/settings.local.json`** | 프로젝트별로 개인이 사용하는 플러그인 |
| **`managed`** | **관리되는 설정** | 조직에서 관리되는 플러그인 (읽기 전용, 업데이트만 가능) |
