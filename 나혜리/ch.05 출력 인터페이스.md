## 출력 스타일
시스템 프롬프트를 수정하여 클로드 코드가 응답하는 방식(역할, 톤, 출력 형식)을 설정하고 변경한다. 
해당 기능은 매 턴마다 동일한 형식을 다시 요청하거나, 클로드가 소프트웨어 엔지니어 이외의 역할을 하기를 원할 떄 사용한다.

---
### 명령어
🚨 책애 표기된 `/output-style` 명령은 v2.1.73에서 더 이상 사용되지 않으며 v2.1.91에서 제거되었다. 

**/config**를 사용하거나 **outputStyle 설정**을 직접 편집해야 한다.

---

클로드 코드의 시스템 프롬프트를 변경하여 **도구의 응답 특성을 근본적으로 조정하는 시스템**으로 결과물의 **형태와 톤을 결정**한다.


> **`CLAUDE.md`에 지침을 추가하는 것과 무엇이 다르지?**
> 
> `CLAUDE.md`에 지침을 추가하여 적용하는 방식은 기존 시스템 프롬프트에 변경없이 해당 지침을 **추가** 하는 거라면 
> 출력 스타일은  기본 지침을 제거하고 **새로운 지침으로 대체**하는 걸 의미한다. 
> 
> 다만, 메인 에이전트 루프의 시스템 프롬프트에만 영향을 미치므로 서브에이전트에는 영향이 미치지 않는다.

결국, 출력 스타일이란 클로드 코드가 어떻게 응답할 지 정의하는 것을 의미한다.

### 내장 출력 스타일
1. `Default`(기본값): 기본 시스템 프롬프트(소프트웨어 엔지니어링에 최적화)
2. `Explanatory`: 구현 선택에 대한 **교육적 인사이트** 제공.
3. `Learning`: 협업 모드(AI 의존도를 줄이기 위해 사용)
4. `Proactive`: 즉시 실행, 계획보다 행동(자동 모드보다 강한 자율 실행 지침이지만 권한 모드 자체는 바꾸지 않아 도구 실행 전 승인 요청은 그대로 뜸)

## 팀 표준 출력 스타일 구축
팀 프로젝트 내에서 일관된 출력 스타일을 공유하기 위해서는 다음과 같은 요소를 고려한다.
1. 팀의 코드 컨벤션과 문서화 표준을 반영
2. 응답의 상세 수준 정의
3. 보안 관련 지침 포함

---

> **질문**
> 
> 팀 프로젝트에서의 출력 인터페이스란 코드 컨벤션의 역할을 하는건가?

**클로드의 답변**

아니요, 코드 컨벤션과 동일한 건 아니에요. 코드 컨벤션은 출력 스타일이 반영해야 할 요소 중 하나일 뿐, 출력 스타일 자체는 더 넓은 범위를 다뤄요.

코드 컨벤션: 코드를 어떻게 작성할지에 대한 규칙(네이밍, 들여쓰기, 문서화 형식 등)
출력 스타일: 클로드 코드가 사용자에게 응답할 때 결과물의 형태와 톤 전체를 결정하는 시스템 프롬프트 수준의 설정
앞서 나온 "팀 표준 출력 스타일 구축"의 3가지 요소를 보면 이 관계가 드러나요.

팀의 코드 컨벤션과 문서화 표준을 반영 → 코드 컨벤션이 출력 스타일 안에 포함되는 입력값
응답의 상세 수준 정의 → 코드 컨벤션과 무관한, 순수하게 응답의 형태에 관한 설정
보안 관련 지침 포함 → 역시 코드 컨벤션과는 다른 차원의 지침
즉, 코드 컨벤션은 출력 스타일이 참조하는 재료 중 하나이고, 출력 스타일은 그 재료를 포함해서 "클로드가 팀에서 어떤 태도와 형식으로 응답해야 하는가"를 정의하는 상위 개념이에요. 팀 프로젝트에서 출력 스타일을 코드 컨벤션 전달 수단으로만 쓸 수는 있지만, 둘은 같은 층위의 개념이 아니에요.

## 출력 스타일과 유사 기능의 비교

출력 스타일 외에도 클로드 코드의 동작을 커스터마이징하는 방법이 여러 가지 있다. 차이는 **시스템 프롬프트를 얼마나/어떻게 건드리는지**에 있다.

| 기능 | 동작 방식 | 적합한 상황 |
|---|---|---|
| **출력 스타일** | 시스템 프롬프트 내용을 통째로 새 지침으로 바꿈 | 매 응답의 역할·톤·형식을 아예 다르게 하고 싶을 때 |
| **CLAUDE.md** | 시스템 프롬프트는 그대로 두고, 뒤에 지침을 추가로 얹음 | 프로젝트 규칙이나 코드베이스 정보를 항상 알고 있게 하고 싶을 때 |
| `--append-system-prompt` | 시스템 프롬프트에 내용을 이어 붙임(기존 내용은 안 지움) | 이번 한 번만 지침을 추가하고 싶을 때 |
| **서브에이전트** | 지침 추가가 아니라, 별도의 독립된 실행 단위를 새로 만들어 위임 | 범위가 명확한 작업을 따로 격리해서 처리하고 싶을 때 |
| **스킬** | 항상 켜져 있지 않고, 필요한 순간에만 관련 지침을 불러옴 | 반복해서 쓰는 작업 절차를 재사용하고 싶을 때 |

> 스킬/서브에이전트/출력 스타일/CLAUDE.md는 대체재가 아니라, 시스템 프롬프트에 얼마나/어떻게 개입하는지가 다른 보완적 도구다.


## 출력 스타일의 환각 방지 지침
**환각**: 존재하지 않는 URL이나 데이터를 제시하거나 확인되지 않은 정보를 단정적으로 서술하거나 실제로 실행하지 않는 검증 결과를 보고하는 형태.

출력 스타일에 **환각 방지 지침**을 추가하면 개별 요청 마다 검증 요구 사항을 반복하지 않아도 일관된 품질을 유지할 수 있어 중요하다.
