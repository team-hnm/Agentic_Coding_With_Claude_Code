## 비대화형 모드와 스크립트 자동화
자동화 파이프라인에서는 대화형 상호작용이 불가능하기 때문에 비대화형 모드를 사용한다. 
명령줄에서 직접 프롬프트를 전달하고 결과를 표준 출력으로 받을 수 있어 셸 스크립트, cron 작업, CI/CD 파이프라인 등에서 클로드 코드의 기능을 활용할 수 있다.

자동화를 위해서는 클로드가 사용할 수 있는 도구를 명시하는 일이 중요하기 때문에 플래그를 명확하게 사용해야 한다.
또한, 대화형 모드와는 다르게 비대화형 모드에서는 **권한 승인** 을 요청하지 않아 도구 제한과 권한 모드를 함께 지정해 사용한다.

> 주로 사용하는 권한 플래그 : `permission-mode`, `allowedTools`, `disallowedTools`
> MCP 설정 플래그 : `--mcp-config`

### 자주 사용하는 플래그
| 플래그                 | 설명                             | 
|------------------------|----------------------------------|
| --continue             | 최근 대화 이어 진행              |
| --resume               | 특정 세션 재개                   |
| --append-system-prompt | 기존 시스템 프롬프트에 지침 추가 |
| --system-prompt        | 기본 시스템 프롬프트 완전 대체   |
| --max-turns            | 에이전트 턴수 제한               |
| --verbose              | 상세 로깅 활성화                 |

### 입출력 형식
비대화형 모드의 입출력 형식도 직접 지정해 사용할 수 있으나 형식의 제한을 두고 있다.

#### 입력
- 텍스트
- 스트리밍 JSON

#### 출력
- 텍스트
- JSON
- 스트리밍 JSON

> JSON vs 스트리밍 JSON
> 
> JSON은 작업이 끝날 때까지 기다렸다가 완성된 결과값을 반환하지만 스트리밍 JSON은 실행되는 동안 한 줄씩 실시간으로 반환한다.
> 
> 따라서, 최종 결과만을 필요로 한다면 JSON을, 진행 과정을 실시간으로 소비해야 한다면 스트리밍 JSON을 선택한다.

### 비대화형 모드 사용 시 고려사항
- JSON 출력 사용
- 오류 처리
- 세션 활용
- 타임아웃 적용
- 속도 제한 존중

## 훅 시스템
훅이란 특정 시점에서 자동으로 실행되는 커스텀 셸 명렁어, LLM 프롬프트 또는 에이전트 작업으로 예측 가능하고 결정론적인 자동화를 구현하는 핵심 매커니즘이다.

이벤트 기반의 자동화 시스템인 훅은 동일한 이벤트에 대해 동일한 로직을 실행하는 일관성의 가치를 지닌 것이 가장 큰 장점이라 할 수 있다.

하지만 강력한 자동화 능력을 제공하는 동시에 보안 위험도 수반하기 때문에 등록 전에 구현을 반드시 검토해야 한다.

### 훅 핸들러 타입
1. **command**: **bash 셸 명렁**을 직접 실행
2. **prompt**: **LLM에 프롬프트를 전달**하여 **단일 턴 평가** 수행
3. **agent**: **서브에이전트**를 생성하여 **다중 턴 검증** 수행

## 훅 이벤트
모든 이벤트는 stdin을 통해 JSON 형식의 입력 데이터를 제공하며 이를 통해 훅 핸들러가 이벤트의 맥락을 파악한다.

### 실행 특성
1. 동일한 이벤트에 대해 여러 훅이 등록되어 있다면 **병렬** 수행한다.
2. 완전히 동일한 훅 핸들러는 자동으로 중복 제거된다.
3. 시간 제한 기본값(timeout 필드로 별도 설정 가능)

   - command: 600초
   - prompt: 30초
   - agent: 60초
4. 훅은 현재 작업 디렉터리에서 클로드 코드의 환경으로 실행된다.
5. 원격 웹 환경에서는 환경변수 `$CLAUDE_CODE_REMOTE`가 `true`로 설정된다. 

### 공통 입력 JSON 필드
| 필드명            | 설명                                |
|-------------------|-------------------------------------|
| `session_id`      | 현재 세션 식별자                    |
| `transcript_path` | 대화 JSON 파일 경로                 |
| `cwd`             | 훅이 호출될 때의 현재 작업 디렉토리 |
| `permission_mode` | 현재 권한 모드                      |
| `hook_event_name` | 발생한 이벤트 이름                  |

### 훅 이벤트 발생 시점별 특징

| 이벤트                  | 발생 시점                                                                                 | 매쳐 지원 |
| -------------------- | ------------------------------------------------------------------------------------- |-----------|
| `SessionStart`       | 세션이 시작되거나 재개될 때                                                                       | O         |
| `UserPromptSubmit`   | 프롬프트를 제출했을 때, 클로드가 처리하기 전                                                             | X         |
| `PreToolUse`         | 도구 호출이 실행되기 전, 실행을 차단할 수 있음                                                           |O         |
| `PermissionRequest`  | 권한 요청 다이얼로그가 나타날 때                                                                    |O         |
| `PostToolUse`        | 도구 호출이 성공적으로 완료된 후                                                                    |O         |
| `PostToolUseFailure` | 도구 호출이 실패한 후                                                                          |O         |
| `Notification`       | 클로드 코드가 알림을 전송할 때                                                                     |O         |
| `SubagentStart`      | 서브에이전트가 생성될 때                                                                         |O         |
| `SubagentStop`       | 서브에이전트가 종료될 때                                                                         |O         |
| `Stop`               | 클로드가 응답을 완료할 때                                                                        | X         |
| `TeammateIdle`       | 에이전트 팀의 팀원이 유휴 상태로 전환되려 할 때                                                           | X         |
| `TaskCompleted`      | 태스크가 완료로 표시될 때                                                                        | X         |
| `InstructionsLoaded` | `CLAUDE.md` 또는 `.claude/rules/*.md` 파일이 컨텍스트에 로드될 때, 세션이 시작할 때와 세션 도중 파일이 지연 로드될 때 발생 |O         |
| `ConfigChange`       | 세션 도중 설정 파일이 변경될 때                                                                    |O         |
| `WorktreeCreate`     | `--worktree` 플래그 또는 `isolation: "worktree"` 설정을 통해 작업 트리가 생성될 때, 기본 작업을 대체함           |X         |
| `WorktreeRemove`     | 세션 종료 시 또는 서브에이전트가 완료될 때 작업 트리가 제거될 때                                                 |X         |
| `PreCompact`         | 컨텍스트 압축이 실행되기 전                                                                       |O         |
| `SessionEnd`         | 세션이 종료될 때                                                                             |O         |

> 매쳐란
> 
> 훅이 발동할 조건을 명시하는 설정값(또는 정규식 문자열)으로 매쳐를 지원하지 않거나, 매쳐를 지원하나 명시하지 않거나 * 를 사용할 경우 모든 상황에서 훅 이벤트가 발동한다.

### 종료 코드
훅의 실행 결과는 종료 코드와 stdout의 JSON 출력이 함께 클로드 코드에 전달된다. 
클로드 코드는 항상 둘 다 읽되, 훅 작성자는 종료 코드만으로 신호를 보내는 방식과 exit 0 후 JSON으로 구조화된 제어를 하는 방식 중 한 가지 패턴을 골라 쓰는 게 권장된다.

- **종료 코드 0**: 성공(기본 동작은 진행). stdout이 `{`로 시작하는 유효한 JSON이면 파싱해서 결정 필드로 사용하고, 아니면 일반 텍스트로 처리
- **종료 코드 2**: 차단 오류. 해당 이벤트가 차단을 지원하면 JSON 출력과 무관하게 무조건 차단됨 — JSON에 `permissionDecision: "allow"`를 써도 뒤집을 수 없음. 단 `reason` 같은 다른 JSON 필드는 계속 읽혀서 차단 사유로 쓰임
- **기타 종료 코드(1, 3 등)**: 코드 자체만으로는 차단 효과 없음. stdout에 스키마 검증을 통과하는 유효한 JSON이 있으면 클로드 코드는 종료 코드를 무시하고 JSON 결정만으로 판단. JSON이 없거나 무효하면 비차단 오류로 처리되어 그냥 진행되고, 트랜스크립트에 `<hook name> hook error` 알림이 표시됨

**예외**: `WorktreeCreate`는 이 표준 모델을 따르지 않아서 JSON 내용과 무관하게 0이 아닌 종료 코드면 무조건 워크트리 생성이 실패하고, `StopFailure`처럼 출력 자체를 아예 무시하는 이벤트도 있음.

#### 출력 범용 필드
- `continue` (기본값 true): false면 클로드 완전 중단
- `stopReason` (기본값 없음): continue가 false일 때 사용자에게 표시되는 메세지
- ~~`suppressOutput` (기본값 false): true면 stdout을 상세 모드에서 숨김~~ 현재는 사용하지 않음
- `systemMessage` (기본값 없음): 사용자에게 표시되는 경고 메세지
- `terminalSequence` (기본값 없음): 데스크톱 알림, 창 제목 또는 벨 소리와 같은 터미널 이스케이프 시퀀스를 출력하도록 지정

### 훅 설정의 기본 구조
훅 설정 파일은 직접 편집하거나 `/hooks` 명령으로 훅 추가, 수정, 삭제 등의 작업을 수행할 수 있다.

1. 훅 이벤트 설택
2. 매쳐 그룹으로 실행 조건 필터링
3. 하나 이상의 훅 핸들러 정의

### LLM을 활용한 고급 훅 타입

#### 프롬프트 기반 훅(prompt)
훅 입력과 개발자의 프롬프트를 클로드 코드 모델에 전송하여 **단일 턴 평가** 수행하며 JSON 형식으로 응답한다. 클로드 코드는 이 결정을 자동으로 처리한다.

#### 에이전트 기반 훅(agent)
단일 LLM 호출 대신 Read, Grep, Glob 같은 도구를 사용할 수 있는 서브에이전트를 생성하여 **다중 턴 검증** 수행하며 최대 50턴까지 실행 가능하다.

#### 비동기 훅(command에서만 지원)
보통의 훅은 실행이 완료될 때까지 다른 작업을 차단하기 때문에 장시간이 걸리는 작업에서는 `"async: ture`로 설정하여 훅을 백그라운드에서 실행하며 완료를 기다리지 않고 즉시 작업을 계속 할 수 있다.

하지만 차단이나 결정 제어가 불가능하며 비동기 훅의 각 실행은 별도의 백그라운드 프로세스를 생성하여 동일한 훅의 여러 실행 간 중복 제거는 수행되지 않으므로 사용에 유의해야 한다.

#### 프론트매터 훅
설정 파일 및 플러그인 외에도 프론트매터를 사용하여 스킬, 서브에이전트에서 직접 훅을 정의할 수 있다.
설정 기반 훅과 동일한 구성 형식을 사용하지만 클로드 코드가 훅을 등록 상태로 유지하는 기간은 구성에 따라 달라진다.

- **서브에이전트 훅**: 해당 서브에이전트가 실행 중일 때만 훅을 실행하고 서브에이전트 실행이 종료되면 제거된다.
- **스킬 훅**: 해당 스킬이 발동할 때 훅을 등록하고, 해당 스킬의 턴 이후를 포함하여 세션이 종료될 때까지 실행한다. 때문에 훅을 한번만 실행하도록 하기 위해서는 `once: true` 설정을 사용한다.

#### HTTP 훅
지정된 URL로 POST 요청을 전송하여 원격 서비스와 연동할 수 있도록 도와주는 훅으로 요청 시, 이벤트 데이터를 JSON 형식으로 본문에 포함하여 전송할 수 있다.
